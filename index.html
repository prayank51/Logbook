FDTL · Flight-time lookback

Flight time within each period ending on your selected reference date.
Reference limits are copied from your supplied image and are editable in the app code: 8:00 / 35:00 / 65:00 / 100:00 / 125:00 / 300:00 / 1000:00. These are user-provided reference values, not independently verified regulatory advice. Confirm current DGCA/company FDTL rules before operational use.
Each window includes the reference date and the preceding days (for example, 7 Days includes the selected date plus the previous 6 calendar days). Flight duration is summed from saved entries by flight date.

Data & privacy

Flight and document records are saved in this browser on this device. This app does not send records to a server. Use Backup regularly and keep the backup file somewhere safe.

Excel import format

Import an .xlsx workbook or .csv file. The app reads the first worksheet and tries to match common column names. The first row should contain headers. After importing, inspect the entries and totals.

Recognised headings include: Date, Aircraft / Registration, Type, From / Departure, To / Arrival, Total Time / Duration, Dual, PIC, Local PIC, Night PIC, Cross Country / XC, Cross Country Dual/PIC, Day Dual, Night Dual, Night, Instrument / IF, Emergency Sortie, Instructor, Take-offs, Landings, Remarks.

If your existing Excel file uses unusual headings or stores flight time in Excel time format, import a copy first and verify the results. Import adds records; it does not automatically delete existing records.

Time entry guide

Enter duration as 1:25 for 1 hour 25 minutes, or as decimal hours such as 1.4 only if that is what your source file uses. For flight entries, use hours and minutes (HH:MM). Category times are not automatically assumed to equal total flight time.

This is a personal tracking aid, not an official DGCA logbook, endorsement, or substitute for your flying school's records. Check applicable DGCA requirements and your instructor's records before relying on any totals.

Install on Android / laptop

  1. Upload the included app files to a static HTTPS host (for example, your own GitHub Pages site) or run from localhost. Opening index.html directly is fine for a quick test, but install/offline caching requires a secure origin.
  2. Open the hosted app once while online. On Android Chrome, use the browser menu → Install app or Add to Home screen. On desktop Chrome/Edge, use the install icon in the address bar or browser menu.
  3. After the app has loaded once, reopen it from the installed icon. The app shell works offline; records stay in that browser profile.
  4. For use on multiple devices, restore a JSON backup separately on each device. Data does not sync automatically.
